1. EXECUTIVE SUMMARY & WHAT IS NEW IN VERSION 2.1.2
================================================================================
CYVRA Mobile Version 2.1.2 is a major engineering and stability release that 
builds upon the Option C Hybrid Sanitization architecture introduced in Version 2.1.1.

While Version 2.1.1 successfully unlocked cryptographic data erasure for consumer 
devices without requiring enterprise Device Owner privileges, field testing 
identified workflow gaps, navigation tab omissions, and bridge timeout errors when 
connecting unauthorized or recently wiped handsets.

Version 2.1.2 resolves every identified field issue while introducing significant 
extra capabilities:

• EXTRA 1: RESTORED 3-TAB NAVIGATION BAR (Top Navigation)
  Restores the missing "Operator Attestation" tab to the main navigation header, 
  enabling instantaneous switching between Inspection, Physical Attestation, and 
  the Transaction Ledger.

• EXTRA 2: DEDICATED 50-SLOT OPERATOR PHYSICAL ATTESTATION GRID
  Full-screen dedicated physical audit interface for all 50 bench slots with an 
  interactive 6-point physical hardware checklist (screen, enclosure, cameras, 
  biometrics, battery swelling, ports/buttons) cryptographically bound to the 
  bench technician's identity.

• EXTRA 3: ZERO-HANG PREFLIGHT TIMEOUT PROTECTION
  Eliminates the 120-second "Bridge Failure: The workstation engine did not answer" 
  timeout. If a phone is in an "unauthorized" or "offline" state (e.g. after a 
  factory wipe before the operator accepts the RSA prompt), the Host engine 
  detects it immediately (<10ms) and displays a clear on-screen instruction: 
  "Target device is unauthorized. Please unlock the phone and tap 'Allow USB debugging'".

• EXTRA 4: ONE-CLICK "SIGN IN & ACTIVATE" ACCESS
  Ensures the corporate Sign In & Activation screen remains accessible on-demand 
  via a prominent [Sign Out] button and dedicated [Enter New Licence Key / Sign In] 
  controls in the Workstation License modal.

• EXTRA 5: CLEANED 50-SLOT TABLE LAYOUT (Clipped Button Removed)
  Removes the legacy clipped "SA" button from populated table rows. Replaces it 
  with clean, responsive columns and moves all stage execution controls into the 
  expandable per-device details card.

• EXTRA 6: SIMPLIFIED STEP 2 HARDWARE SCAN WIZARD
  Eliminated the redundant "OPERATOR ID (OPTIONAL)" input field from Step 2 of the 
  Scan Wizard, centralizing technician attribution in the header bar and Step 6.

• EXTRA 7: UPDATED ON-DEVICE ANDROID AGENT v2.1.2
  Upgrades `com.cyvra.sanitization` to Version 2.1.2 (versionCode = 3). Supports 
  automatic agent version synchronization across all 50 USB slots.

• EXTRA 8: FOOLPROOF AUTOMATED POWERSHELL BUILD ENGINE
  Introduces `build-cyvra-2.1.2.ps1` with permanent parameter quoting, automatic 
  path resolution, and end-of-build cryptographic checksum verification.

5. DEDICATED 50-SLOT OPERATOR PHYSICAL ATTESTATION ENGINE
================================================================================
Physical device condition is distinct from software-collected telemetry. The 
Operator Physical Attestation screen allows bench technicians to record physical 
hardware checks that cannot be sensed over USB:

A. 6-Point Physical Hardware Checklist:
   1. Display / Touchscreen : Physical cracks, display bleed, dead pixels, touch accuracy.
   2. Outer Enclosure       : Chassis dents, housing cracks, liquid ingress indicators.
   3. Camera Lenses         : Front and rear lens scratches, cracks, optical clarity.
   4. Biometric Sensors     : Fingerprint scanner surface integrity, facial sensor glass.
   5. Battery Physical State: Evidence of swelling, expansion, deformation, or heat damage.
   6. Physical Buttons/Ports: USB charging port wear, power/volume tactile response.

B. Cryptographic Binding:
   • Each answer is recorded as PASS, FAIL, or NOT_APPLICABLE.
   • Attestation answers are sealed with the active technician's Operator ID.
   • Merged into the Final Verification Report and stamped with a SHA-256 digest.

6. INSTANT PREFLIGHT DEVICE READINESS & ZERO-HANG TIMEOUT PROTECTION
================================================================================
In Version 2.1.1, if a device was connected but sitting in an `unauthorized` state 
(e.g., after a factory wipe or before accepting the computer's RSA key), ADB 
commands would hang and retry, eventually exceeding the 120-second IPC bridge 
timeout and generating a red "Bridge Failure" banner.

Version 2.1.2 implements instant pre-flight device validation in `HostProtocolDispatcher.kt`:
1. When `RUN_SCAN` is invoked, the engine checks `adbClient.listDevices()` in <5ms.
2. If the target serial is `unauthorized`, it halts immediately and returns:
   - Code   : `DEVICE_NOT_READY`
   - Message: `Target device <serial> is unauthorized. Please unlock the phone and tap 'Allow USB debugging' when prompted.`
3. If the target serial is in state `offline` or disconnected:
   - Code   : `DEVICE_NOT_READY`
   - Message: `Target device <serial> is in state '<state>'. Ensure the device is powered on and unlocked.`
4. Zero UI Freezes: Eliminates the 120-second stall completely, delivering an 
   instant, friendly instruction directly to the bench technician.

8. OPTION C HYBRID SANITIZATION & 5-TIER QUALIFICATION ENGINE
================================================================================
Evaluates device telemetry dynamically to qualify the optimal sanitization method:

• TIER 1: CLEAR_DEVICE_OWNER_WIPE
  - Conditions: Device Owner active (`deviceOwnerActive == true`).
  - Action    : Dispatches authorized enterprise wipe via `DevicePolicyManager.wipeData()`.
  - Standard  : NIST SP 800-88 R1 "Clear".

• TIER 2: PURGE_CRYPTOGRAPHIC_ERASE
  - Conditions: File-Based Encryption (FBE) active (`storageEncryptionStatus == 5` or 
    `isEncrypted == true`) and hardware-backed KeyStore present.
  - Action    : Destroys Master KEK/DEK encryption keys, evicts credentials, and 
    formats data partition via recovery.
  - Standard  : NIST SP 800-88 R1 "Purge" (Cryptographic Erase). Data is mathematically 
    unrecoverable.

• TIER 3: PURGE_OEM_SECURE_ERASE
  - Conditions: Samsung / Google OEM secure recovery erase service available.
  - Action    : Triggers authenticated OEM hardware secure erase command block.
  - Standard  : NIST SP 800-88 R1 "Purge".

• TIER 4: CLEAR_PLATFORM_RESET
  - Conditions: Legacy Android device without FBE, or unencrypted storage.
  - Action    : Dispatches authorized recovery factory reset (`--wipe_data`).
  - Standard  : NIST SP 800-88 R1 "Clear".

• TIER 5: TECHNICAL_BLOCKER
  - Conditions: Rooted kernel detected, modified bootloader, or tampered su binary.
  - Action    : Sanitization refused; outputs explicit technical reasoning.

9. MULTI-SIGNAL POST-RESET VERIFICATION & ZERO-RESIDUAL INTEGRITY PROOF
================================================================================
CYVRA Mobile never assumes a reset succeeded without post-wipe verification:
1. `device_provisioned` Verification: Must return `0` (pristine OOBE state).
2. Zero Account Invariant: 0 Google, Samsung, or enterprise accounts remaining.
3. Zero Third-Party App Invariant: 0 user applications remaining on `/data/app`.
4. Screen Lock Eviction: Keyguard confirmed unconfigured; credentials evicted.
5. Invariant Reporting: Full audit numbers included in final certificate.

12. IMMUTABLE TRANSACTION LEDGER & 1-CREDIT BILLING INVARIANTS
================================================================================
A. Append-Only Ledger (`<cyvra.home>/ledger.jsonl`):
   • Records all events: ACTIVATION, HW_SCAN, APP_SCAN, SANITIZE_START, SANITIZE_VERIFY.
   • SHA-256 hash-chained: each entry carries the hash of the preceding record.
   • Dual verification: verified in both Rust (`ledger.rs`) and TypeScript (`parseLedger.ts`).

B. Strict 1-Credit Billing Invariant:
   • 1 scan credit is debited ONLY upon a fully verified, successful sanitization.
   • Blocked sanitizations, failed verifications, or diagnostic scans debit 
     EXACTLY ZERO CREDITS (`scansRemaining` balance is never deducted).
