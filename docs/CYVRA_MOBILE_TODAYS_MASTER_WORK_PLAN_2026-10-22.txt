======================================================================
1. ORIGINAL PRODUCT OBJECTIVE — PRESERVED
======================================================================

CYVRA Mobile is a Windows 10/11 workstation application for Android device evidence collection, verification, reporting, and controlled sanitization.

The intended customer journey is:
1. Connect and identify a supported Android device.
2. Collect only legitimately available, non-destructive evidence.
3. Produce Report 1, officially named "CYVRA Device Verification Report", before sanitization.
4. Obtain separate, explicit sanitization authorization and verify live entitlement.
5. Execute only a supported, qualified sanitization method.
6. Reconnect, verify the outcome using appropriate evidence, and issue a final report whose claims match what was actually performed and verified.

Architecture boundary:
- React/TypeScript: desktop presentation and operator interaction.
- Rust/Tauri: Windows-native USB/PnP/WPD/MTP truth and process lifecycle.
- Kotlin/JVM: domain logic, Android semantics, capability policy, licensing, workflow, evidence, and reports.
- Android component/APK: supporting device-side evidence, not the workstation orchestrator.
- Cloudflare Worker + Neon: account, entitlement, registry, audit, and cloud coordination.
- Resend: server-side transactional email.
- CYVRA Mobile remains a separate product/repository/infrastructure from CYVRA Erase.

Programme sequence:
CONSOLIDATE -> CORRECT -> INTEGRATE -> HARDWARE-PROVE -> RELEASE-PROVE

Evidence/maturity terms must remain distinct:
MODELLED -> UNIT-TESTED -> PROTOCOL-EXPOSED -> UI-INTEGRATED -> HARDWARE-VALIDATED -> RELEASE-VALIDATED

A compile, mock, unit test, launcher, or source file does not by itself prove an integrated customer capability.
