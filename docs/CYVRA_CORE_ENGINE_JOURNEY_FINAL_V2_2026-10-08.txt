SECTION 3 — PURGE METHOD PUR-DO-WIPE (sanctioned, conditional)
Flow: controlled ADB → install signed CYVRA Sanitization Agent →
adb shell dpm set-device-owner <agent> (precondition: NO accounts) →
STATUS 10-Oct-2026: the agent is built, installed and enrolled on D-P5, but is
NOT yet release-signed. Signing awaits the keystore-custody ruling; until then
"signed" above is the target state, not the present state. →
agent DevicePolicyManager.wipeData(flags) → userdata wipe ERASES THE AGENT
(no userdata trace) → reboot to setup wizard → ASSISTED RECONNECT
(technician re-authorizes ADB) → post-purge evidence chain → report.
Preconditions: debugging authorized; device-owner slot free; OEM matrix row
verified; recorded authorization + ownership attestation (SECTION 6).
FRP reality: platform self-blocks enrollment on FRP-locked devices without
owner credentials; CYVRA never bypasses. Owner-supplied credentials are
entered only by owner/operator and recorded as owner evidence.
Trace honesty: host-side pre-wipe logs exist and are disclosed; userdata is
trace-free post-wipe. Report states limitations (no NAND claim, Spec §29).

SECTION 4 — IDENTIFIER & TRACKING POLICY
Never fabricate (Spec §24). IMEI = OPERATOR-captured evidence (photo of
*#06# / sticker / About) with photo reference; no software extraction A10+.
CYVRA Device Token = sha256(model + build fingerprint + storage CID sysfs
where available + battery/display serials where available); stable across
wipe; same-device confirmation key (Spec §28). Restricted states recorded
verbatim (NOT EXPOSED / RESTRICTED / NOT COLLECTED).

SECTION 5 — ML CORE / PATCH / TELEMETRY (advisor-actor, reproducible)
5.1 Core ML engine lives in this repository (governed). Trains offline on
    fixture corpus + OEM documentation + fleet telemetry. Never in the
    customer actuation path.
5.2 Output = CAPABILITY PATCH: versioned, ed25519-signed JSON:
    {patch_id, engine_min_version, matrix_rows[], procedure_overrides[],
     oem_scope, evidence_refs, created_by, approved_by}.
5.3 Customer engine executes ONLY signed patches matching engine_min_version.
    Engine version + patch-set version recorded in EVERY report
    (reproducibility invariant).
5.4 Field uplink: on-connect + periodic check-in (configurable cadence).
    Payload = engine version, patch set, capability challenge events,
    host system logs. NO customer device evidence content without explicit
    consent; consent recorded; withdrawal honored; offline queue.
5.5 Shadow learning: predictions logged vs ground truth; promotion to patch
    only via governed PR + Chief Engineer approval.
5.6 No runtime self-modification of actuation logic.

SECTION 6 — LEGAL T&C CLAUSES (draft — legal review required)
6.1 Ownership warranty: customer warrants lawful possession/authority and is
    SOLELY responsible for verifying devices are not stolen/lost/encumbered.
    CYVORIQ relies on the recorded attestation.
6.2 Authorization record: every purge requires an explicit in-app
    authorization event (operator, timestamp, ownership category, attestation
    hash) reproduced in the report.
6.3 Credentials: lock/FRP credentials entered only by owner/operator; CYVRA
    never solicits or stores plaintext credentials.
6.4 Limitation of assurance: supported evidence paths only; no NAND-level
    warranty; post-purge verification = stated evidence only.
6.5 Telemetry consent: scope, cadence, retention, withdrawal.
6.6 Indemnity: customer indemnifies CYVORIQ for unlawful-device processing;
    governed by laws of India (seat to be finalized by legal).
