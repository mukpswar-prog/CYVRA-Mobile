PART 3: THE 18 OCTOBER TIMESTAMPS IN C:\Program Files\CYVRA Mobile
================================================================================
Why did some files and folders have "18 October" timestamps previously?
Was the installer packaging stale resources?

Here is the plain-English explanation of why that happened:

1. Windows Folder Creation Dates:
   When Windows installs software into "C:\Program Files\CYVRA Mobile", it creates 
   that folder on the day of the first installation (for example, 18 October). 
   If you later run an update or overwrite installer over the existing directory, 
   Windows keeps the original folder creation timestamp (18 October) for the outer 
   folder, even when the files inside are brand new!

2. Genuine Vendor Driver Files:
   Inside the installer's "resources\drivers" folder, there are official, digitally 
   signed device drivers from Samsung and Google:
   - Samsung USB drivers (ssudadb.inf, ssudbus.sys): Digitally signed by Samsung 
     Electronics in April 2026.
   - Google WinUSB driver (android_winusb.inf): Digitally signed by Microsoft / 
     Google in June 2025.
   Because these are official signed drivers, their file timestamps MUST reflect the 
   exact date and time the vendor signed them. If their dates or bytes are modified, 
   their digital signature breaks, and Windows will refuse to install them!

3. Google Platform Tools:
   The adb.exe tool and its companion DLLs come directly from Google's official 
   Android platform-tools release (dated September 2026).

4. What WAS Freshly Built vs What Is Vendor-Signed:
   - Host Core JAR files (host.jar, core.jar): Freshly built yesterday (01 Nov 2026).
   - Android Sanitization Agent APK (cyvra-agent.apk): Freshly compiled and signed 
     yesterday (01 Nov 2026).
   - Desktop Application Executable (cyvra-mobile-desktop.exe): Freshly compiled 
     yesterday (01 Nov 2026).
   - Java 21 Runtime (jlink): Assembled on 31 Oct 2026.

Conclusion:
The newly built installer did NOT contain obsolete core software. The older dates 
you saw belonged either to vendor-signed driver packages (which must never be re-dated) 
or were Windows folder timestamps from a previous installation.

PART 4: STEP-BY-STEP MANUAL GUIDE TO BUILD A 100% CLEAN .EXE INSTALLER
================================================================================
To build a completely fresh, brand-new CYVRA Mobile installer from scratch with 
ZERO chance of carrying leftover or cached files, follow these exact 6 steps 
in Windows PowerShell:

--------------------------------------------------------------------------------
STEP 1: CLEAN ALL PREVIOUS BUILD ARTIFACTS
--------------------------------------------------------------------------------
Open PowerShell in the project directory:
C:\Users\User\.gemini\antigravity\worktrees\CYVRA-Mobile\version_two_feature_audit

Run these cleaning commands:
  # 1. Clean Android agent and Host Java builds
  Push-Location apps\android
  .\gradlew.bat clean
  Pop-Location

  # 2. Clean Desktop frontend build folder
  Push-Location apps\desktop
  if (Test-Path dist) { Remove-Item -Recurse -Force dist }

  # 3. Clean staged resources so everything must be re-created fresh
  if (Test-Path src-tauri\.resources\host) { Remove-Item -Recurse -Force src-tauri\.resources\host }
  if (Test-Path src-tauri\.resources\agent) { Remove-Item -Recurse -Force src-tauri\.resources\agent }
  Pop-Location

What this does: Completely wipes all compiled temporary files, ensuring nothing old 
can be reused.

--------------------------------------------------------------------------------
STEP 2: BUILD AND SIGN THE ON-DEVICE ANDROID AGENT (v2.1.1)
--------------------------------------------------------------------------------
Run:
  Push-Location apps\android
  .\gradlew.bat :sanitization-agent:assembleRelease -Pcyvra.signing.mode=test --console=plain
  Pop-Location

What this does: Compiles the Android agent source code and produces the signed APK 
file: apps\android\sanitization-agent\build\outputs\apk\release\sanitization-agent-release.apk

--------------------------------------------------------------------------------
STEP 3: BUILD THE HOST ENGINE JAR PACKAGES
--------------------------------------------------------------------------------
Run:
  Push-Location apps\android
  .\gradlew.bat :host:installDist --console=plain
  Pop-Location

What this does: Compiles all Kotlin backend code, Option C qualification engine, 
PDFBox 3.0.3 report generator, and packages all 10 Host distribution JARs.

--------------------------------------------------------------------------------
STEP 4: STAGE FRESH INSTALLER RESOURCES
--------------------------------------------------------------------------------
Run:
  powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stage-windows-installer-resources.ps1 -SigningMode test -Force

What this does:
• Copies the fresh Host JARs into apps\desktop\src-tauri\.resources\host\lib\
• Copies the signed 2.1.1 agent APK into apps\desktop\src-tauri\.resources\agent\
• Verifies the Java 21 jlink runtime and platform-tools.
• Harvests the genuine Samsung and Google USB drivers.

--------------------------------------------------------------------------------
STEP 5: COMPILE THE DESKTOP FRONTEND (REACT & TYPESCRIPT)
--------------------------------------------------------------------------------
Run:
  Push-Location apps\desktop
  pnpm.cmd build
  Pop-Location

What this does: Runs TypeScript type checking (`tsc -b`) and Vite production bundler 
to produce the fast, minified desktop user interface in `apps\desktop\dist`.

--------------------------------------------------------------------------------
STEP 6: ASSEMBLE THE FINAL WINDOWS NSIS INSTALLER (.EXE)
--------------------------------------------------------------------------------
Run:
  $env:CYVRA_SIGNING_MODE = 'test'
  Push-Location apps\desktop
  pnpm.cmd tauri build
  Pop-Location

What this does:
• Compiles the native Windows Rust desktop application with release optimizations.
• Bundles the frontend, Java runtime, Host JARs, drivers, and agent APK into a 
  single per-machine Windows installer.
• Outputs the final executable at:
  apps\desktop\src-tauri\target\release\bundle\nsis\CYVRA Mobile_2.1.1_x64-setup.exe

--------------------------------------------------------------------------------
HOW TO PERFORM A 100% CLEAN TEST INSTALLATION ON WINDOWS:
--------------------------------------------------------------------------------
1. In Windows "Settings -> Apps -> Installed Apps", uninstall any existing "CYVRA Mobile".
2. If "C:\Program Files\CYVRA Mobile" still exists, delete it completely.
3. Run the newly built `CYVRA Mobile_2.1.1_x64-setup.exe` installer.
4. When you open "C:\Program Files\CYVRA Mobile", the main folder will have today's 
   current date and time, the application executable will be fresh, and all software 
   components will be version 2.1.1.
